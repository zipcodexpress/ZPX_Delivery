## Confirmed findings

1. **Admin login does not preserve Terminal452 behavior.** Terminal452 `Manage/frmAdminLogin.cs` accepts a code/card from the cabinet's `zp.db` roster, refreshed by `getAdminCardList`. New `Delivery/NativeAdminClient.cs` requires email/password and Delivery NETWORK privileges. An existing locker admin code cannot pass it. Restore code entry and the existing cabinet-scoped authority, with no invented default or public unauthenticated import control.
2. **Admin screen prioritizes form fields over the locker.** It requires tower, door and a typed reason; the diagram starts at y482, outside the small-screen viewport. Put the diagram and door action together, replace mandatory free-text reason with a recorded standard admin action, and retain operation history/recovery.
3. **API health is presented as broader readiness.** `/health/ready` checks API/PostgreSQL, not admin-code support, scanner, controller or completed parcel workflows. Keep technical details in diagnostics and preserve actual server error messages for diagnosis instead of replacing all failures with generic connectivity text.
4. **Compatibility API gap.** Delivery implements the TP8 config-token endpoint and Delivery cabinet projection, but not the Terminal452 admin roster API. Original configuration points to `http://zpxapi:8088`, unresolved on this development PC. Do not point old TP8 calls blindly at Delivery or claim all legacy APIs have been ported.
5. **Physical acceptance is incomplete.** Previous builds validate synthetic frames and screens; the connected Windows7 locker has not supplied measured end-to-end evidence here. Local serial inventory is empty. Keep software test results distinct from operator-observed door/scanner behavior.
6. **Documentation overstates completion in places.** Native admin maintenance is only selected-door opening/recovery. Terminal452 also has selected/bulk opening, logs, settings and apartment parcel management. Delivery workflows still need complete physical/customer/carrier acceptance against the project journey; source presence and a green health endpoint are insufficient.

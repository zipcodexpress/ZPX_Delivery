## Running checks

Normal startup: `python3 scripts/dev.py up`. It selects `.env.dev`, not `.env.prod`.
Use explicit Compose configuration:

```sh
docker compose --project-directory "$PWD" --env-file .env.dev -f deployment/compose.yaml exec -T api php bin/providers.php payment
docker compose --project-directory "$PWD" --env-file .env.dev -f deployment/compose.yaml exec -T api php bin/providers.php hosted
docker compose --project-directory "$PWD" --env-file .env.dev -f deployment/compose.yaml exec -T api php bin/providers.php reporting
docker compose --project-directory "$PWD" --env-file .env.dev -f deployment/compose.yaml run --build --rm --no-deps mail-worker php bin/providers.php mail
```

These checks do not send an email or submit a charge. `mail-test ADDRESS` is a
separate explicit send action; only run it for an authorized allowlisted recipient.
Do not print expanded Compose configuration or raw provider responses.

Set `PAYMENT_PROVIDER=AUTHORIZE_NET_SANDBOX`, sandbox login/transaction/signature
keys, and `AUTHORIZE_NET_ENVIRONMENT=sandbox` in private configuration. Only new
checkouts use the chosen adapter; existing LOCAL_TEST attempts remain unchanged.

For approved automatic email delivery, set `MAIL_DELIVERY_MODE=smtp` and an explicit
`MAIL_ALLOWED_RECIPIENTS` list, inspect queued SMTP jobs, reload API environment,
and explicitly start the `mail-worker` service. Older LOCAL_ONLY messages remain
untouched. Do not enable this until the user authorizes future verification sends.

## Automated verification and limits

`npm run check`, `npm run build`, Python tooling tests and `python3 scripts/dev.py test-db`
passed locally and cover generated contracts, web builds, existing identity/shipping/concurrency and
new provider/messaging regressions. Provider tests inject transports and never
contact external services. The suite completion guard now returns failure even
when ThinkPHP's CLI exception handler would otherwise exit with status zero.

Unfinished: native apps; physical origin deposit, driver pickup and hub receipt;
SMS provider; production payments; refunds and ambiguous-checkout recovery; public
webhook delivery. An expired token never offers an unverified replacement checkout.

Operator browser inspection confirmed the sandbox payment, invoice/transaction reference,
$6.00 amount and committed shipment history render correctly. The signed-in staff
session was preserved. Six local application/proxy/simulator readiness checks passed.

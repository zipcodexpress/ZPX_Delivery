# P1.2 identity increment

Purpose: document implemented behavior and executed evidence. Audience: developers/reviewers.
Status: local identity slice implemented; full P1.2 and launch readiness remain incomplete.
Owner: unassigned. Verified: 2026-09-19.

## Implemented

- ThinkPHP routes under `/api/delivery/v1` for register, login, contact challenge,
  contact verification, refresh, logout and current profile.
- Single configured ZPX organization and customer-only public registration. Explicit
  field validation rejects role/organization injection and malformed request bodies.
- Bcrypt passwords; authenticated encryption for contacts/addresses; keyed lookup
  hashes; opaque session credentials stored only as hashes. No secrets in API logs.
- Separate email/phone proof, expiring one-use six-digit challenges, five-attempt
  lockout, durable rate limits, neutral challenge responses for unknown contacts.
- Development verification messages encrypted in the transactional outbox. The private
  CLI inbox exports only unexpired, unconsumed messages; no code is returned by HTTP.
- Browser cookies, CSRF and origin checks; native refresh rotation/replay-family
  revocation; logout audit/idempotency; current disabled-account checks.
- Site-scoped role authorization and organization consistency constraints in migration 005.
- Customer registration/sign-in/contact-verification screens; staff sign-in screen.
  Both use the generated contract types and existing API proxy.
- Demo identities acquire synthetic contacts without changing existing passwords/roles.
- Docker web file polling fixes missed Colima filesystem events.

The canonical OpenAPI and generated types now document browser CSRF fields, logout's
empty JSON body, password/code bounds and sanitized errors. Historical migrations
001–004 are unchanged. The schema now has 75 tables including the ledger and auth limiter.

## Evidence

`python3 scripts/dev.py test-db` runs each suite in a unique temporary Compose project
with a fresh PostgreSQL volume. Cleanup addresses only that project's resources;
the persistent developer dataset remains intact. Database/HTTP tests cover encryption,
registration restrictions, duplicate contacts, invalid credentials, contact-code replay,
verification attempt persistence, cross-user/organization/site denial, expired grants,
CSRF/origin checks, cookie attributes, disabled users and logout revocation.

Two independent processes contend on one refresh family. The test observes database
lock waiting, then checks one successful rotation and one rejected replay; every
descendant is revoked. Existing ownership/last-compartment, migration and rollback
tests remain included. The setup suite checks private inbox output and cleanup scope.

The live customer proxy was also exercised with existing synthetic credentials:
browser-cookie login → own profile → email and phone local verification → verified
profile → CSRF logout → rejected old session. Passwords/cookies/codes were not printed.

Browser inspection verified desktop registration/sign-in layouts, a 390px layout and
the neutral invalid-login response. Browser inspection also detected and confirmed the
fix for stale Vite modules under Colima. This is not a full browser automation suite.

Final local checks passed: `npm run check` (nine JavaScript tests plus contract/type
checks), both web builds, eight Python setup tests, strict Composer validation,
static handoff validation, the isolated PHP/PostgreSQL suite and all six live readiness
targets. Repeated `demo-accounts` added zero contacts and retained passwords/grants.
The private inbox export was created with owner-only permissions. An initial logout
test incorrectly compared JSON object key order after JSONB storage; it now compares
the operation/status fields and additionally verifies exactly one audit event.

their workflows are not silently implemented as registration proof. Device enrollment,
legacy account-link assertions, administrative staff provisioning, password recovery,
key rotation/retention policies and production deployment hardening remain outstanding.
No public shipping, payments, physical door commands or production access occurred.

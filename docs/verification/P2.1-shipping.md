## Executed evidence

`python3 scripts/dev.py test-db` uses a fresh random Compose project, then removes only its
own resources. PostgreSQL integration checks exercise unauthorized/unverified senders,
forged actor fields, fit/same-site rejection, encrypted recipient snapshots, non-enumerating
claims, fresh proof, failed-attempt persistence, single-use and idempotent claims, recipient
read without sender mutation permission, same-customer sending/receiving, expired and
site-limited staff grants, cross-organization denial, and hub location versus actual custody.

Two independent PHP processes submit one command under a held advisory lock; the test
observes both waiting in PostgreSQL, releases them, and verifies the same single shipment ID.
Cancellation retries resolve their original response before stale version checks and produce
one event. Payment checks cover cross-user denial, pending duplication, replay, production
refusal, expired quote rejection, unchanged physical custody, label eligibility, stable SI/QR
on reprint, print-request retry deduplication and revoked-label rejection. Routing checks cover
anonymous access, browser CSRF, staff-only HTTP queue, dynamic shipment routes and PDF auth.

A live HTTP smoke through the customer Vite proxy additionally completed draft → quote →
LOCAL_TEST pending → server test confirmation → authenticated PDF. Existing synthetic customer
and recipient accounts claimed each other's shipments through fresh local codes. Two demo
shipments remain for testing, one outgoing paid-test and one incoming draft for the primary
customer. Only the existing recipient test account's local contacts were verified; no actual
email/SMS, real payment or physical command was sent. Passwords and credentials were not printed.

The PDF was rendered with `pdftoppm`, visually inspected, and its QR independently decoded
with zxing-cpp against the actual issued payload. No clipping was observed. This is rendered
QR verification, not a physical printer/scanner commissioning claim. The sample is retained
locally at `.local/shipping-test-label.pdf`, outside Git.

Browser inspection covered the customer wizard's actual form and site options, the operator
queue, paid-test detail/history, and 390px responsive operator detail with no horizontal overflow.
The browser already held the admin session; the full customer happy path was tested through
HTTP rather than a claimed full browser automation run. Temporary viewport overrides were reset.

Failures caught and fixed: missing test namespace import; extra parenthesis in staff scope SQL;
ThinkPHP strips route extensions, so authenticated PDF uses `/packages/{id}/label/pdf` rather
than an unmatched `.pdf` path. A regression check now requires that PDF path to match and reject
anonymous access. The API contract operation-count assertion was updated to 63.

Final local verification also passed `npm run check` (63-operation canonical contract,
generated types, TypeScript and nine JavaScript tests), both web production builds,
eight Python setup tests and the handoff validator. Toolchain: Node 24.19.0,
PHP 8.3.33, PostgreSQL 17.11, FPDF 1.9.0, BaconQrCode 3.1.1. Composer dependency
resolution reported no security advisories. Live startup passed all six readiness targets.

## Completion boundary

P2.1/P2.2 are not fully complete: Authorize.net adapter/sandbox checks, real rate/service policy,
refund handling, supervised label replacement, scanner resolver and native mobile remain.

this increment neither skips nor marks those gates complete. Provider choice is Authorize.net;
its sandbox account/credentials are the next external dependency.

# Contributing

1. Read the root README, project AGENTS instructions and current handoff execution contract.
2. Select an existing backlog task ID and create an issue describing the desired behavior and acceptance evidence.
3. Create a branch such as `feature/P1.1-customer-identity` or `docs/clarify-custody`.
4. Change code, affected specifications, API/schema contracts and meaningful tests together. Resolve contradictions explicitly.
5. Run relevant checks and record exact commands and results. Distinguish simulated behavior from physical evidence.
6. Open a pull request using the supplied template. Link the issue and request review when collaborators are available.
7. After merging, update issue status and milestone evidence. Mark DONE only when required evidence exists.

Never commit secrets, real customer records, production database exports or local environment files. Use synthetic fixtures and placeholder-only environment examples.

For writing conventions, sources of truth and status reporting, see [the documentation guide](docs/DOCUMENTATION_GUIDE.md).

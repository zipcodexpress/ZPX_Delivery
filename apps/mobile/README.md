# Customer and driver mobile app

One Expo/React Native app serves customer and driver accounts on Android and iOS. It uses the existing ZPX Delivery API; no separate mobile account database is created.

Both roles have **Use locker · Scan terminal QR**. Choose a task on the terminal, scan its `ZPXPAIR` QR code in the app (or enter the full code), check the site/action and approve. Customers can send or collect; carriers can collect from an assigned arrived inbound stop or deposit at an arrived outbound stop. Sending/carrier parcels use the existing terminal label scanner after approval. Recipient pickup lists the account's ready parcels at the paired destination and obtains a one-use pickup grant. Session status follows the terminal; closure alone never transfers custody. Confirm only the parcel actually placed/removed, on the terminal or in the app after observed closure. If it was not deposited, use the terminal's No/size-change controls. Re-scan the same terminal scene to resume an existing session after leaving the screen. The browser terminal-companion is a development fallback, not required for mobile users.

Camera access is requested only when scanning; denial permits manual entry or Settings. New native builds must include the expo-camera plugin; microphone permission is disabled. Android/iOS JavaScript export does not establish camera or physical-locker readiness. Phone testing requires a reachable API origin: the current Windows API binds loopback, so `EXPO_PUBLIC_API_URL=http://127.0.0.1:8000` only works on the API machine, not on a phone.

From the repository root, run `npm install`, then `npm run ios --workspace=@zpx/mobile` to start Metro and open Expo Go in the iOS simulator. **Keep that command running** while using the simulator; Expo Go needs Metro and shows “Could not connect to the server” when it stops. On macOS you can also double-click `start-ios.command` in this folder to open a dedicated Terminal window that keeps Metro running. The iOS script forces IPv4 localhost because this machine otherwise binds Metro to IPv6 while Expo Go opens IPv4. `npm run dev:mobile` starts Metro without opening a simulator. Set `EXPO_PUBLIC_API_URL` to the API origin your device can reach. The development defaults are `http://localhost:8000` on the iOS simulator and `http://10.0.2.2:8000` on the Android emulator. A physical phone needs a reachable API address; do not use `localhost` on the phone. Production builds require an explicit HTTPS `EXPO_PUBLIC_API_URL`.

Sign in with an existing customer or approved driver account. The app stores the rotating native refresh token in the operating system's secure store and holds the short-lived access token in memory. Customer navigation includes a dashboard, shipments and tracking, searchable location map/list with per-site details, a three-step shipment draft, profile and primary-address editing, saved-card summaries, and payment history. Real sites with coordinates offer directions in the phone's maps app. Local synthetic sites have illustrative orange pins and no directions; never use those positions for travel or parcel drop-off. Sites without coordinates remain available in the list with an explicit map-unavailable message. Card details remain with the payment provider; hosted card management, quote/checkout, label and recipient-claim flows are not yet mobile flows.

Driver navigation separates inbound collection (Driver in) and outbound delivery (Driver out), plus earnings and profile. Assigned runs use compact tappable rows matching the customer shipment list; pull down to refresh run lists, earnings or profile. The driver profile has grouped editing for contact, license, address, emergency contact, vehicle and insurance details using the existing self-service API; status and verification remain read-only, and changing document information does not automatically update verification. Drivers can view offers and assigned runs, acknowledge a published run, verify a label before recording an inbound pickup or outbound load, confirm outbound departure, and report stop arrival. Scan entry currently accepts a label token typed or supplied by an external scanner; on-device camera capture and durable interrupted-network recovery still need implementation and testing before field release. The app does not issue locker hardware commands. Final locker deposit continues through the existing terminal-paired workflow.

Shared screens use compact type and spacing while retaining 48pt main controls. Profile editors keep Save/Cancel visible, show validation beside those actions, and pair short fields only when screen width and font scale allow it. Customer editing focuses on the form; driver editing groups fields into collapsible sections. Larger font scales use full-width profile fields. iOS forms use keyboard avoidance; Android uses the native resize behavior.

Validation: `npm run check` and `npm run build --workspace=@zpx/mobile`. `APP_ENV=production` requires an explicit HTTPS API URL. Live Expo Go checks confirmed customer sign-in, dashboard, shipments, tracking, location map/list and site selection, profile and payment history, plus driver sign-in, inbound/outbound navigation, run detail and earnings. Custody mutations were not exercised against local fixtures. Native device testing remains required before release. Expo Go includes `react-native-maps`; a standalone Android release needs a configured Google Maps API key before its map can be validated. Expo Go runs on the local iPhone simulator, but a standalone iOS build on Xcode 26.2 currently fails in Expo SDK 57's `expo-modules-jsi` ([upstream issue](https://github.com/expo/expo/issues/50067)); use a compatible Xcode toolchain or wait for its fix. An Android debug APK built locally, but the existing emulator lacked space to install it. Generated `ios` and `android` directories are local build outputs and ignored by Git.
